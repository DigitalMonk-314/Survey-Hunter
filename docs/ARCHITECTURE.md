# Survey Hunter — Архитектура проекта

**Версия:** 0.3.0  
**Статус:** Ранняя разработка  
**Назначение:** Персональный агрегатор маркетинговых и социологических исследований в Telegram.

## 1. Цель системы

Survey Hunter собирает объявления из 10 публичных Telegram-каналов, определяет публикации об опросах и исследованиях, извлекает ссылки и основные условия участия, оценивает соответствие профилю респондента и отправляет подходящие объявления в личные сообщения.

Автозаполнение анкет, веб-интерфейс и мультипользовательский режим не входят в MVP.

## 2. Архитектура компонентов

### 2.1. Источники

- 10 публичных Telegram-каналов.
- Идентификаторы и usernames хранятся в конфигурации или таблице `sources`.
- Система обрабатывает новые публикации и сохраняет идентификатор исходного сообщения.

### 2.2. Parser — Telethon

Модуль `parser.py` отвечает за получение новых сообщений через пользовательский Telegram-аккаунт.

Извлекаемые данные:
- текст сообщения;
- подпись к фотографии или другому медиа;
- URL из текста и форматирования;
- URL встроенных кнопок, если они присутствуют.

Парсер не принимает решений о релевантности и не отправляет уведомления.

### 2.3. Pipeline — конвейер обработки

Модуль `pipeline.py` координирует обработку сообщения:

1. Нормализация текста.
2. Проверка повторов.
3. Фильтрация по ключевым словам.
4. Извлечение ссылок.
5. Извлечение признаков объявления.
6. Расчёт оценки соответствия профилю.
7. Сохранение подходящих объявлений.
8. Передача уведомлений через асинхронную очередь.

Обработка ошибок и защита от повторной отправки обязательны.

### 2.4. Filters — фильтрация и признаки

Модуль `filters.py`:
- ищет ключевые слова и их варианты;
- извлекает ссылки из текста и кнопок;
- определяет город, возраст, пол, вознаграждение, длительность, формат и тематику;
- сохраняет неизвестные значения как неопределённые, а не как подтверждённое несовпадение.

Наличие ссылки на Google Forms не является обязательным условием для каждого объявления.

### 2.5. Scoring — оценка релевантности

Модуль `scoring.py` оценивает соответствие объявления профилю респондента.

Профиль загружается из `profile.yaml`. Порог оценки задаётся через конфигурацию.

В MVP используется система правил и весов без LLM-классификатора.

### 2.6. Database — хранение данных

Модули `models.py` и `db.py` определяют структуру данных и операции SQLite.

Основные сущности:
- `sources` — источники публикаций;
- `messages` — найденные объявления;
- `feedback` — действия пользователя.

Дедупликация выполняется по хешу нормализованного текста и ссылок. При необходимости идентичность опроса и идентичность исходной публикации учитываются раздельно.

### 2.7. Notifier — уведомления

Модуль `notifier.py` использует aiogram 3.x.

Уведомление включает:
- краткое описание объявления;
- извлечённые условия участия;
- вознаграждение и длительность, если известны;
- ссылку или ссылки;
- название исходного канала;
- действия пользователя через inline-кнопки.

Команды управления: `/stats`, `/pause`, `/profile`.

### 2.8. Configuration — настройки

- `config.py` — загрузка и валидация настроек.
- `.env` — секреты и параметры окружения.
- `profile.yaml` — профиль респондента.
- `requirements.txt` — зависимости Python.

Секреты и файл сессии Telethon не должны попадать в Git.

## 3. Технологический стек

| Назначение | Технология |
|---|---|
| Язык | Python 3.11+ |
| Telegram-клиент | Telethon |
| Бот уведомлений | aiogram 3.x |
| База данных | SQLite |
| Асинхронный доступ к БД | aiosqlite |
| Настройки | pydantic-settings, python-dotenv |
| Профиль | PyYAML |

| Запуск | systemd или tmux |

## 5. Надёжность и безопасность

- Не логировать токены, пароли и коды авторизации.
- Не коммитить `.env` и сессию Telethon.
- Обрабатывать сетевые ошибки и временные ограничения Telegram.
- Предусмотреть корректное завершение клиентов и очереди.
- Использовать ограничения уникальности и транзакции SQLite.
- Не отправлять одно уведомление повторно при перезапуске без необходимости.
- Не считать объявление актуальным только потому, что оно найдено в канале.

## 6. Границы MVP

В MVP входят сбор публикаций, фильтрация, извлечение признаков, скоринг, хранение, уведомления и сбор обратной связи.

Не входят:
- автоматическое заполнение Google Forms;
- веб-дашборд;
- LLM-классификатор;
- мультипользовательский режим;
- Docker, если он не понадобится для развёртывания.

## 7. Критерии готовности

- Бот обрабатывает новые публикации из заданных каналов.
- Извлекает ссылки из текста и кнопок.
- Отбирает объявления по правилам и профилю.
- Не создаёт повторные записи и лишние уведомления.
- Сохраняет действия пользователя.
- Корректно восстанавливается после ошибок и перезапуска.
- Имеет тесты для фильтров, скоринга и базы данных.
